# Build Onedit from the release source

Download the source, browser runtime and Host SDK archives plus the release checksum file. Verify all three archives against checksums obtained through the release page before extracting. The source archive contains MIT App and SDK source. The runtime archive carries the separately licensed Core binaries, browser assets, local launcher and fonts. The SDK archive is the ready-to-install distribution; its code and public types can also be built from `sdk/`.

## Run without building

Use Node.js 22 or later. In the extracted runtime directory:

```sh
node start-ai-editor.mjs 4173
```

Open http://127.0.0.1:4173/ in a browser. Standalone editing does not require an external service. Embedding is denied unless you configure exact parent and editor origins and supply an authorization provider. This distribution does not supply production authorization or TLS. Check the same archive's `AI-BROWSER-CHANNEL.md`.

To install the SDK into a separate consumer directory:

```sh
npm install --offline --ignore-scripts ./onedit-ai-host-sdk-1.0.0-rc2.tgz
node --input-type=module -e 'import { OneditHostClient, version } from "onedit-ai-host-sdk"; console.log(typeof OneditHostClient, version)'
```

Run the SDK contract tests from the source workspace or from the unpacked SDK archive. There is no registry publication. The local sample uses its own pinned editor runtime and does not depend on an older private editor build.

## Reproduce the browser assets and SDK modules

With Node.js **22.23.1** and npm **10.9.8**, run from a clean copy of the extracted source:

```sh
npm ci --ignore-scripts --no-audit --no-fund
node scripts/replay-public-release.mjs ../onedit-runtime
npm --prefix sdk run build
npm --prefix sdk run verify:release
npm --prefix sdk test
```

Replace `../onedit-runtime` with the actual extracted runtime directory. The App and build-tool lockfiles pin TypeScript 6.0.3 and esbuild 0.25.12. With both lockfile caches populated, the same build can be run offline. The replay command verifies the source inputs and all four files from `build-inputs/core/` before strict TypeScript checking and bundling. It verifies actual generated files against the released hashes. It does not fetch or compile Rust.

The asset namespace is a digest of the sorted build input path-to-SHA256 map, including source, the Core build manifest, bundler scripts and the bundler lockfile. A development checkout that changes any of those inputs naturally gets different names, imports and HTML. No option forces a stale asset prefix. The expected pin is a verification assertion in `RELEASE-BUILD-RECIPE.json`; it is not passed as the build namespace.

- **Clean App builds:** independent clean builds of the same pinned inputs can be compared using their build inventories.
- **Exact release browser files:** the replay checks the 34 generated runtime files, including the UI chunks, HTML, manifest, styles, fonts and staged Core payloads. The rest of the runtime archive consists of supplied launcher and notice/provenance files and is checked by the release archive inventory. It is not generated by the UI compiler.
- **SDK:** the published TypeScript source rebuilds the SDK's 12 shipped JS/declaration files byte-for-byte. TypeScript also emits two empty JS modules for type-only source; neither ships in the installable release archive. The byte check is for the shipped module set, not a claim that recreating the tarball produces its original container bytes.
- **Core:** binary provenance and matched-file verification only. Upstream RHWP is MIT; this is a modified build. Downstream Rust sources and Cargo.lock are not distributed. See [Core provenance](CORE-BUILD-PROVENANCE.md), [Core notice](THIRD_PARTY_CORE_NOTICE.md) and the runtime's full Core license. Noto fonts remain OFL 1.1 and Hancom HCR fonts retain their separate noncommercial redistribution conditions.

Building or matching files does not substitute for independent release acceptance.
